# 需求文档 — 播过的古诗和英语媒体可离线再播

> 创建时间：2026-11-03
> 需求级别：L1

## 0. L1 SPEC 最小契约（L1 必填，L2 可扩展）

| 字段 | 内容 |
|------|------|
| 目标 | 古诗朗读和英语跟读在成功播放后留在本机，断网后仍能播放已留下的内容 |
| 非目标 | 不预下载整库；不保证从未播放过的内容离线可用；不做账号同步 |
| 影响范围 | 网页古诗页、网页英语页、小程序古诗页、小程序英语页的媒体地址选择与本机存储 |
| 验收证据 | AC-01～AC-04：`node --test tests/offline-policy.test.js tests/offline-store.test.js`；网页用本地缓存命中断言；小程序用假 wx 下载并淘汰 |
| 回滚路径 | 移除离线模块并恢复播放页直接使用网络地址；本机缓存可留在设备上，不参与回滚 |
| 安全自治判定 | AGENT_AUTO_APPROVED。目的已由用户确认；文件清单固定；只写本机缓存，不改接口、权限和生产配置；验证用 node:test 与浏览器点播 |

对抗分析裁剪理由：用户已确认「播过再留下、音频优先、视频只留最近几课」，没有第二种产品方案。

## 1. 需求背景

- 当前业务背景：古诗与英语媒体从 Cloudflare 或本地 HTTP 在线播放，只有进度存在本机。
- 触发原因：用户要求断网后仍能播放。
- 现状问题：断网后已听过的课也无法再播。

## 2. 目标与成功标准

- 业务目标：学习内容在第一次成功播放后可离线复听。
- 用户目标：地铁或没网时继续听已经听过的古诗和英语。
- 成功指标：缓存命中时播放地址不再依赖网络；超出视频条数或总容量时删掉最久未用的条目。

## 3. 用户角色与使用场景

- 用户角色：使用网页或微信小程序的学习者。
- 使用入口：`gushi/index.html`、`english/index.html`、小程序古诗页和英语页。
- 使用路径：在线播放成功 → 本机留下文件 → 断网后再次打开同一首/同一课。
- 关键场景：古诗音频、英语音频尽量多留；英语视频只留最近 3 课。

## 4. 功能需求

| 编号 | 功能点 | 描述 | 输入 | 输出 | 规则 | 异常处理 |
|------|--------|------|------|------|------|----------|
| FR-01 | 播放后留下 | 媒体开始播放后把完整文件存到本机 | 媒体 id、地址、类型 | 缓存条目 | 音频与视频都可留；同一 id 只保留一条并更新使用时间 | 下载失败保持在线播放，不打断当前声音 |
| FR-02 | 离线再播 | 再次打开时优先用本机文件 | 媒体 id 或地址 | 本机地址或原网络地址 | 本机文件缺失则回退网络地址并删掉无效索引 | 没有缓存且断网时沿用现有失败提示 |
| FR-03 | 容量淘汰 | 控制本机占用 | 现有索引、新条目、上限 | 保留列表与淘汰列表 | 视频最多 3 条；总容量 120MB；先淘汰超出的旧视频，再淘汰最久未用的音频 | 新条目本身超过容量时仍保留这一条 |

## 5. 涉及的接口/数据定义

| 定义文件 | 结构体/类型 | 相关字段 | 用途 |
|----------|------------|----------|------|
| shared/offline-policy.js | 缓存条目 | id、app、kind、bytes、lastUsed、path 或 url | 淘汰计算，不包含文件内容 |

本需求不新增服务端接口。

## 6. 非功能需求

- 性能：缓存下载不替换正在播放的地址，避免把当前课打断。
- 安全：只缓存本站媒体地址，不接收外部传入的任意下载目标。
- 兼容性：网页用 Cache Storage；小程序用本地文件。无相关 API 时继续在线播放。
- 可维护性：淘汰规则放在无界面模块，网页和小程序共用。

## 7. 范围边界

- **本次要做：** 播过自动留下、再次优先本机、视频 3 条与 120MB 淘汰、网页壳的离线回退。
- **本次不做：** 整库预下载、缓存管理页、跨设备同步、古诗配图离线。
- **默认假设：** 单课视频约 12MB，3 条视频加音频可以放进 120MB。
- **依赖条件：** 第一次播放时网络可用；小程序本地文件配额允许保存。

## 8. 验收标准

| 编号 | 验收条件 | 验证方式 |
|------|----------|----------|
| AC-01 | 第 4 条视频会淘汰最久未用的那一条，只留 3 条 | node:test |
| AC-02 | 总容量超出时先淘汰旧音频，不先删仍在名额内的视频 | node:test |
| AC-03 | 小程序索引能记录保存路径，文件丢失时回退并删除索引 | node:test 假 wx |
| AC-04 | 网页播放成功后写入缓存，下次解析到 blob 地址 | node:test 假 Cache Storage；浏览器打开英语页确认脚本无报错 |

## 9. 风险与待确认问题

经逐条审查，无待确认问题。用户已确认缓存范围。

## 10. 对下游 Agent 的交接说明

- 给方案设计 Agent：淘汰规则必须可单测；播放中的网络地址不被中途替换。
- 给开发 Agent：网页与小程序分两套存储，共用 `shared/offline-policy.js`。
