## 1. 方案目标

- 解决问题：给 `english/` 媒体一个可恢复进度的播放页，并为小程序留同一套数据和动作。
- 需求映射：FR-01/02/04/08 靠扫描脚本和 `catalog.js`；FR-03/06 靠 `app.js`；FR-05/07 靠 `progress.js`、`platform.js` 和 `miniprogram/`。

## 2. 现状分析

- 当前相关代码实现方式：工作区里还没有播放页。参考实现是远程仓库 `gushi/` 的静态页：`index.html` 透传 sharecode，`js/app.js` 拉取 JSON、画分组目录、控制一个 audio 元素。
- 现有代码文件：`english/` 下只有两个媒体目录，没有 html/js。
- 可复用组件/模式：古诗页的纸色、侧滑目录、底部上一首/播放/下一首、进度条和语速按钮。语速在古诗页里默认 0.85 且只能循环；本页改为默认 1 并弹出选项。

## 4. 详细设计

### 4.1 组件设计

| 组件名 | 职责 | Props | State | 位置 |
|--------|------|-------|-------|------|
| 列表页 | 展示视频、音频两组及文件夹 | 清单、搜索词 | 当前 id | `english/index.html` |
| 播放页 | 视频画面或音频唱片、标题、控制条 | 当前媒体 | 播放、拖动、倍速菜单 | `english/js/app.js` |
| 目录模块 | 识别扩展名、分组、编码地址 | 文件名或清单项 | 无 | `english/js/catalog.js` |
| 进度模块 | 读写快照、把临近结尾的时间折回 0 | 存储接口 | 无 | `english/js/progress.js` |
| 平台存储 | localStorage 或 wx 同步存储 | 环境对象 | 无 | `english/js/platform.js` |
| 小程序适配器 | 把播放、暂停、跳转、倍速映射到微信上下文 | wx、进度模块 | 音频上下文、视频时间 | `english/miniprogram/player-adapter.js` |

### 4.2 数据流设计

- 扫描脚本写出 `english/data/media.json`。
- 页面 `fetch` 清单后调用 `groupCatalog`，视频在前、音频在后。
- 打开时 `readProgress`。媒体仍在清单中则进入播放页，等 `loadedmetadata` 后再把 `currentTime` 设为记忆值，不自动播放。
- `timeupdate` 约每秒写入一次；暂停、跳转、`pagehide` 立即写入。
- 状态在页面闭包内，进度在 `english-player-progress-v1`。

## 7. 方案取舍

| 方案 | 优势 | 劣势 | 是否采用 |
|------|------|------|----------|
| 扩展名分类 + 纯函数进度 + 网页元素与小程序适配器分开 | 音频目录里的视频不会混进去；网页现在能播；小程序以后接同一 JSON | 多一个适配文件 | 是 |
| 只按文件夹名分成两栏 | 实现更短 | `P8 Extend.mp4` 会留在音频栏，不符合“不要混在一起” | 否 |
| 直接在网页里写 wx API | 少一个文件 | 浏览器里没有 wx，页面会被拖垮 | 否 |

## 8. 风险与待确认问题

| 编号 | 问题 | 风险 | 影响 | 建议确认角色 |
|------|------|------|------|-------------|
| R-01 | mkv、mov 在部分浏览器不能播 | 列表里有，点开失败 | 页面提示格式不受支持 | 接受，不转码 |
